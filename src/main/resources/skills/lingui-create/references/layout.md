# 组合与视觉层次

先识别主要任务：阅读说明、选择作答、查看数据或提交表单。主操作应紧挨它影响的内容，辅助说明使用 caption，页面或作品标题使用 h2，分组标题使用 h3，正文使用 body。同一层级使用相同文字样式。

用 Column 组织纵向流程，Row 仅放少量能在窄屏自然排列的同级内容。Section 提供标题、简短说明和内容组，Card 仅在边界表达真实分组时使用。信息已经分组时，避免再套一层卡片；不要把每行文字都装成卡片。容器支持哪些对齐属性，以本次查询到的 schema 为准，不生成 gap、padding、width 等未支持字段。

没有指定风格时，从当前作品主题延续设计；新作品可采用 theme 参考中的清晰蓝，radius 6–10、spacing 12–20、shadow 0–1。用户指定的风格优先，包括尖角、高对比度或紧凑布局。ThemeTokens 控制颜色、圆角和间距，组件负责内容层次和布局，不能往节点里塞 CSS。

- 接口作品：用途说明 → 获取/刷新按钮 → 加载/具体错误/空结果/正常结果。按钮、内容和状态提示放在同一个内容组，真实数据加载前保持空值。
- 测验：题干 → 选项 → 与选择对应的解析 → 重新作答。不要为了装饰额外加入进度条、评分或仪表盘。只有用户需要多题时才增加题目导航。
- 数据概览：标题和统计口径 → 2–4 个指标 → 明细。指标单位写在 label 或 description。数据是示例时直接标注，不能假装已连接真实服务。
- 表单：每个字段有可识别的 label，必填/错误提示靠近字段；主要提交按钮只有一个，提交中使用 loading，失败保留输入供修正。

先用少量组件把信息顺序和交互做对，再完善主题。需要可靠结构时读取 get_guidance(topic="examples")；已有清晰方案无需额外读取所有范例。
